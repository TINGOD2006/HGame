## 3. 遊戲設計規格（完整版）

### 3.1 核心循環（三層）

```
【分鐘級】戰鬥 15–60 秒 → 節點獎勵 → 探索度上升
     ↓
【小時級】一天 10–15 分鐘：白天 1 行動點（迷宮/採集/委託/訓練）
                        夜晚 1 行動點（關係事件/送禮/約會/整備）
     ↓
【全局】章末檢查雙軸 → 解鎖分支 → 新迷宮 → 終章結局
```

- 每日 2 行動點（白天／夜晚各 1），章節共 7–10 天。
- 設計飛輪：迷宮素材 → 鍛造／禮物 → 關係與戰力 → 支援技 → 更深迷宮。
- 失敗不 Game Over：戰敗退回據點，損失當日探索進度 30%。

### 3.2 戰鬥

- 編制：主角＋2 名夥伴（女主角可選 1–2 名出戰）。
- 節奏：一般 30–60 秒、精英 2 分鐘、Boss 3–5 分鐘。
- 行動順序：可見行動條（AGI 決定），非即時 ATB。
- 屬性：斬／打／火／冰／影 5 屬性；命中弱點累積破防值。
- 共鳴值（Resonance）：隊伍共享 0–100；命中弱點＋連攜累積；用於合體技與支援技。
- 女主角支援技：信賴軸→治療／護盾／復活／行動加速；慾望軸→增傷／破防／異常／追擊；雙軸皆高→專屬合體技（每人 1 招）。
- **MVP 簡化**：主角 1 人＋女主角支援技（每場 1 次）、3 屬性（斬／火／冰）、共鳴滿 100 放合體技（傷害 ×2.5）。

### 3.3 迷宮（節點式）

- 完整版：每章 1 座迷宮、5–8 層、每層 8–12 節點。
- 節點類型：戰鬥／精英／事件／寶箱／休息／商店／隱藏（探索度門檻）／Boss。
- 探索度 0–100%：影響掉落品質、隱藏節點出現率、章末評價。
- 撤退：保留 70% 戰利品；戰敗損失 30%。
- **MVP**：1 座 × 3 層、每層 8 節點、探索度每節點 +12%、撤退保留 70%。

### 3.4 據點

- 設施：鍛造（裝備／禮物）、藥房、酒館（委託／情報）、神殿、自宅（關係事件）。
- 派遣：派女主角執行 1 天任務，帶回素材與小事件（低成本內容槓桿）。
- 經濟：金幣＋迷宮素材雙軌，避免單一貨幣通膨。
- **MVP**：只做鍛造（武器強化）、送禮、約會；不做藥房／派遣／商店。

### 3.5 關係雙軸（核心差異點）

| 軸 | 範圍 | 提升方式 | 解鎖 |
|---|---|---|---|
| 信賴 | 0–100 | 正確對話、共同戰鬥、實用禮物、守約 | 純愛／羈絆事件、輔助支援技、個人結局 |
| 慾望 | 0–100 | 夜晚互動、特定道具、迷宮誘惑事件 | 背德／激情事件、攻擊支援技、另一種結局 |

**四象限（章末檢查）**

| 信賴 | 慾望 | 狀態 | 調性 | 走向 |
|---|---|---|---|---|
| 高 | 低 | 摯友／伴侶 | 溫暖、守護 | 純愛結局 |
| 低 | 高 | 危險的依存 | 張力、失控 | 沉淪結局 |
| 高 | 高 | 靈魂伴侶（隱藏） | 濃烈、互信 | 真結局條件 |
| 低 | 低 | 陌生人 | 無事件 | 不影響主線 |

設計原則：兩軸不是善惡；不看成人內容也能通關；關係等級提升要有可見回饋（表情、稱呼、戰鬥台詞）。

### 3.6 成人內容框架（只談結構）

| 層級 | 觸發 | 完整版數量 | 可否跳過 | 作用 |
|---|---|---|---|---|
| ① 主線場景 | 章節推進 | 5–8 | 可淡出／跳過 | 敘事高潮 |
| ② 關係事件 | 雙軸門檻 | 20–30（每角色 5–8） | 可跳過＋替代獎勵 | 主要獎勵層 |
| ③ 收集型 | 迷宮／失敗／隱藏 | 8–12 | 可跳過 | 探索誘因 |

- 每角色 ② 層至少 3 種調性；事件與主線因果掛鉤；差分（表情／服裝）優先於新增整張 CG（1 CG + 3 差分 = 4 段內容）。

### 3.7 世界觀與角色

- 邊境城鎮「艾爾斯特」建在古代迷宮上；迷宮每數十年「活性化」湧出魔物與魔力結晶；主角是唯一能承受深層瘴氣的人，代價是記憶與壽命。
- 主角：沉默主角、玩家可命名；動機＝解自身詛咒＋城鎮羈絆。
- 反派：表層＝掌控結晶交易的鎮長；深層＝迷宮核心「回聲」（歷代犧牲者集體意識，以誘惑／交易引誘主角留下）。

## 5. AI 美術策略

**結論**：可以用 AI，但要付代價＝**曝光**＋**角色魅力**。

| 平台 | 申報 | 曝光懲罰 |
|---|---|---|
| Steam | 必須申報玩家可見生成內容（pre-generated／live-generated 分開），純效率工具免報 | 無直接降權，但玩家看得到揭露標籤 |
| DLsite | AI 使用 ON/OFF 必填 | 隔離到「AI 生成」專區、一般搜尋看不到；月 3 作品上限 |
| FANZA 同人 | 三階段：AI 生成／AI 一部利用／AI 補助 | AI 生成作品不進首頁／新著／排行；月 3；申報不實可停權 |
| BOOTH | 無明文 | 被檢舉可強制非公開 |
| pixivFANBOX | — | 全面禁止 AI 生成 |
| Patreon | 需符合社群規範 | 無降權，違規可停權 |
| itch.io | 需申報 | 成人內容全面 deindex（與 AI 無關） |

**著作權**：純 AI 輸出在台／美／日難主張著作權；有實質人類加工的部分可能受保護但舉證困難 → 保留 prompt、seed、草圖、修改前後對照。模型商用條款各異，商用前逐一確認。

**對本作的衝擊**：① 曝光是命脈，DLsite／FANZA 正是 AI 懲罰最重的平台；② 4 女角一致性需 LoRA＋大量人工修；③ 精準差分 AI 難「只改一個變數」；④ 成人向玩家對 AI 味容忍度低。

**工作流**：人工畫師主導女主角立繪／主線 CG／封面；AI 生成背景／雜兵／道具／UI 並人工修、申報「AI 一部利用」；先做「風格聖經」3–5 張再量產；用 AI 把委外需求從 80 張降到 40 張。

**MVP 決定**：AI 輔助先出全套草稿；但角色定稿（三視圖＋2 服裝）完成並鎖定 reference 後才量產，否則等於製造廢圖。建立 `AI_使用登記表.csv`（檔名、工具、prompt、seed、人工修改說明、AI 比例、最終用途）。

## 6. MVP 範圍（凍結）

**唯一要驗證的兩件事**：① 循環（迷宮→戰利品→據點→關係）好不好玩；② 成人內容作為獎勵層是否自然、跳過是否空虛。

**保留（必做）**

| 模組 | 規格 |
|---|---|
| 迷宮 | 1 座 × 3 層、節點式（戰鬥／事件／寶箱／休息／Boss）、探索度、撤退 |
| 戰鬥 | 回合制、3 屬性弱點、共鳴值 1 招合體技；敵人 3 種＋Boss 1 |
| 據點 | 日夜各 1 AP；鍛造（武器強化）、送禮、約會 |
| 關係 | 1 位女主角、雙軸各 0–100、3 個事件（含 1 個成人向） |
| 系統 | 存檔、事件旗標、回想模式、跳過成人場景＋替代獎勵 |
| 內容量 | 文本 1.5–2.5 萬字、CG 2 張（含差分）、立繪 1 角 × 3 表情 × 2 服裝、背景 4 張、BGM 5 首 |
| 時長 | 45–60 分鐘 |

**砍掉**：4 位女主角、技能樹、商店／派遣／藥房、隊伍系統、多結局、畫廊 UI、在地化、配音、音效打磨。

> 資料結構必須預留 4 位女主角欄位（`heroine_id`、`trust`、`desire`），否則擴充時重寫。

**MVP 資產清單**：立繪（6 臉層＋2 身體）、CG 2 張＋差分 4、背景 4、敵人 4、UI 1 套、BGM 5、SE 20、字型 1–2（中文授權需確認）。

**MVP 戰鬥數值（起始建議）**

| 對象 | HP | ATK | DEF | AGI |
|---|---|---|---|---|
| 主角 | 120 | 18 | 8 | 12 |
| 史萊姆 | 40 | 8 | 4 | 6 |
| 蝙蝠 | 55 | 10 | 5 | 14 |
| 石像（精英） | 160 | 14 | 15 | 5 |
| Boss 迷宮守衛 | 480 | 22 | 12 | 10 |

公式：`傷害 = max(1, ATK × 技能倍率 − DEF × 0.5) × 弱點倍率(1.5) × 隨機(0.9–1.1)`。
共鳴：命中弱點 +15、受擊 +5。
節奏目標：一般戰鬥 ≤30 秒、Boss 2–3 分鐘。

## 7. 技術方案（Unity）

| 項目 | 設定 |
|---|---|
| Unity | 6000.3.10f1（Unity 6 LTS 線） |
| 範本 | 2D (URP)；不用 2D 光源，MVP 靠 Sprite 排序與 UI |
| 輸入 | Input System（新版） |
| UI | uGUI（不用 UI Toolkit） |
| 序列化 | Newtonsoft Json（`com.unity.nuget.newtonsoft-json`） |
| 建置 | Windows Standalone x64 |
| 版本控制 | Git＋Unity `.gitignore`＋Git LFS（大圖） |
| 授權 | Unity Personal（年營收 < 20 萬美元） |
| 不做 | Addressables、ECS/DOTS、自訂 Shader、多人連線 |

**專案結構**

```
Assets/_Project/
├── Art/{Characters,CG,Backgrounds,UI}
├── Audio/{BGM,SE}
├── Data/{Json,ScriptableObjects}     # events / heroines / enemies / dungeon / items
├── Scripts/{Core,Data,Battle,Dungeon,Town,Relationship,Dialogue,UI}
├── Prefabs/
├── Scenes/                            # Boot, MainMenu, Town, Dungeon, Battle
└── Settings/
```

**Scene 職責**

| Scene | 職責 |
|---|---|
| Boot | 初始化、載入設定、存檔檢查 |
| MainMenu | 新遊戲／繼續／回想／設定 |
| Town | 據點日夜循環、設施、關係事件（事件以 UI Overlay 播放，不切場景） |
| Dungeon | 節點地圖、探索、撤退 |
| Battle | 回合制戰鬥，結束返回 Dungeon |

**常駐**：`GameBootstrap`（DontDestroyOnLoad）持有 `GameContext`（存檔資料、旗標、雙軸）。
**跨場景原則**：所有跨場景狀態只放 `GameContext`，Scene 內物件一律可重建。

### 7.1 資料格式（事件 JSON 範例）

```json
{
  "id": "s1_night",
  "type": "relationship",
  "conditions": { "flags": ["dungeon2_clear"], "minTrust": 30, "minDesire": 20, "dayMin": 3 },
  "skippable": true,
  "skipReward": { "gold": 150, "item": "herb_pack" },
  "presentation": { "bg": "inn_night", "cg": "serena_cg_01", "heroine": "serena", "expr": "shy" },
  "inkPath": "Data/Ink/s1_night.ink"
}
```

- `type`：`story` / `relationship` / `collect` / `adult`。**成人場景只是一種事件類型**，不做特例。
- 全年齡版＝把 `adult` 事件的 `inkPath` 換成 safe 版或停用；程式不動。

### 7.2 存檔

```json
{
  "version": 1,
  "day": 3, "chapter": 1,
  "flags": ["dungeon2_clear"],
  "heroines": [ { "id": "serena", "trust": 35, "desire": 22, "seenEvents": ["s1_drink"] } ],
  "player": { "hp": 120, "level": 3, "skills": ["slash","fire"] },
  "inventory": { "gold": 480, "items": { "herb_pack": 2 } },
  "unlockedCg": ["serena_cg_01"]
}
```

- 路徑：`Application.persistentDataPath/saves/slot_1.json`、`auto.json`；MVP 手動 1 槽＋自動 1 槽。
- **原子寫入**：寫 `.tmp` → `File.Replace`；`SaveMigrator` 依 `version` 補欄位。

### 7.3 資料驗證器（Editor 工具）

一鍵檢查：事件 id 唯一、`inkPath` 存在、條件 flag 有被 set、`presentation.cg` 在解鎖清單、敵人／道具引用存在、事件可達性簡查。

## 8. 架構設計

### 8.1 分層

```
Presentation（Unity）：Scenes / MonoBehaviour / uGUI
Application（Unity，薄）：EventRunner / DialogueService / SaveSystem / SceneLoader / AudioService
Domain（純 C#，不引用 UnityEngine）：GameContext / BattleModel / DamageCalculator /
    DungeonGraph / RelationshipService / EventAvailabilityService / SaveData
```

Assembly Definition：`Game.Core`（Domain）、`Game.Unity`、`Game.Editor`、`Game.Tests`。

**理由**：一人開發最貴的是驗證時間；Domain 用 EditMode Test 毫秒驗證，Presentation 只負責畫。代價：多 2–3 天寫介面。

**規則**：Domain 不碰 `GameObject`、`Sprite`、`Coroutine`、`Time.deltaTime`；隨機傳 `IRng`。

### 8.2 Domain 類別

| 類別 | 職責 | 關鍵方法 |
|---|---|---|
| `GameContext` | 全局可變狀態（日、章、旗標、女主角、玩家、背包、解鎖 CG） | `AdvanceDay()`、`GetHeroine(id)` |
| `HeroineState` | trust / desire / seenEvents | `AddTrust(n)`、`AddDesire(n)` |
| `GameFlags` | 具名旗標集合（序列化字串陣列，好除錯） | `Set`、`Has` |
| `RelationshipService` | 雙軸規則、四象限 | `Quadrant(id)` |
| `EventAvailabilityService` | 掃出可播事件並排序 | `GetAvailable(context)` |
| `BattleModel` | 純資料戰鬥狀態機 | `Step(action)`、`IsOver` |
| `DamageCalculator` | 傷害公式（靜態可測） | `Compute(...)` |
| `DungeonGraph` | 節點圖生成 | `Generate(floorConfig, seed)` |
| `SaveData` / `SaveMigrator` | 存檔 POCO 與遷移 | `Migrate(json)` |

### 8.3 Unity 類別

`GameBootstrap`、`SceneLoader`、`EventRunner`、`DialogueService`、`SaveSystem`、`TownController`、`DungeonController`、`BattleController`、`AudioService`。UI 只讀狀態、發事件，不直接改 Domain。

### 8.4 事件與 Ink 邊界

- **JSON**：觸發條件、演出（BG／CG／立繪／BGM）、獎勵、可否跳過、替代獎勵。
- **Ink**：台詞、選項、對話內分支。
- **Ink external**：`getTrust(id)`、`getDesire(id)`、`addTrust(id,n)`、`addDesire(id,n)`、`hasFlag(name)`、`setFlag(name)`、`giveItem(id,n)`。
- **Ink 不存 state**（MVP 事件不中途離場）；演出不放進 Ink，確保雙版本可換。
- D7 一致：`EventRunner` 只串流程，規則在 Domain；超過 300 行就拆。

### 8.5 典型時序

**A. 夜間事件**

```
DayCycleController.EndDay()
 → GameContext.AdvanceDay()
 → EventAvailabilityService.GetAvailable(context)
 → EventRunner.Play(event)
     → 載入 presentation → DialogueService.Play(ink) ↔ externals 讀寫 GameContext
     → 套用 effects（gold/item/flag/seenEvents）→ 記錄 CG
 → SaveSystem.AutoSave()
```

**B. 迷宮→戰鬥→回城**

```
DungeonController.EnterNode(battle)
 → SceneLoader.Load(Battle)（帶 enemyId 與種子）
 → BattleController 初始化 BattleModel → 回合循環 → 勝負
 → 寫回 GameContext（HP、掉落、探索度）
 → SceneLoader.Load(Dungeon)（還原節點位置）
```

### 8.6 測試策略

| 層級 | 測什麼 |
|---|---|
| EditMode | 傷害公式、四象限、事件條件、存檔遷移、節點生成 |
| PlayMode | Boot→MainMenu→Town→Dungeon→Battle→回城 煙霧測試 |
| 手動 | 每日循環、事件跳過、回想重播 |

原則：Domain 每個公式至少 1 個測試，追求「改數值不會炸」。

### 8.7 已知陷阱

1. Ink 卡住超過 2 天 → 切回自製 JSON Runner，不要硬撐。
2. `EventRunner` 變上帝類別 → 超過 300 行拆。
3. AI 素材匯入規格不一致 → 先定 PPU／解析度／命名，用 `AssetImportPresetter` 統一。
4. 場景切換狀態遺失 → 跨場景狀態只放 `GameContext`。
